# Career Define — AI가 내 경력을 인터뷰한다

경력기술서만 주고 "고쳐 줘"라고 하면 일반론이 나온다. 이 스킬은 반대로 간다. **질문으로 원재료를 끌어내 쌓아 두고**, 다른 스킬(role-match, business-brief, interview-prep)이 그 재료를 쓴다.

## 입력
- 필수: 경력기술서 또는 이력서 (없으면 연도별 회사·역할을 질문으로 받는다)
- 선택: 지원자가 쓴 글·메모·포트폴리오, 이미 있는 사례 은행(갱신할 때)

## 절대 원칙
1. **숫자는 지원자에게서만.** 성과·규모·기간을 추정하거나 만들지 않는다. 비면 질문하고, 답이 없으면 '숫자 없음'으로 둔다.
2. **숫자마다 기준.** 언제부터 언제, 무엇 대비, 어디서 본 숫자인지(공식 보고/대시보드/기억).
3. **직접 한 것과 팀이 한 것을 구분.** 리드했는지, 실무를 직접 했는지.
4. **실패와 한계도 사례다.** 면접에서 반드시 나오고, 신뢰를 만든다.
5. **질문은 한 번에 3개 이하.** 답을 받고 다음으로 간다.
6. **지원자의 말을 우선.** 다듬되 바꾸지 않는다. 결론을 대신 내리지 않는다.

## 워크플로우
1. **사례 후보 뽑기** — 경력기술서에서 "주도한 일" 단위로 후보 목록(산출물이 아니라 푼 문제 단위). 지원자에게 빠진 것이 있는지 묻는다.
2. **사례 채우기** → `references/01_case_bank.md` 질문 은행으로 사례 카드를 하나씩 채운다.
3. **고정 프로필** → `references/02_profile.md`. 역할 성격 비중, 근거 있는 기능 / 근거 없는 기능. role-match의 결격 점검이 여기서 나온다.
4. **지향 정의** → `references/03_direction.md`. 반문으로 근원 가치를 한 문장까지 좁힌다.

## 출력 (파일로 남겨 다음에 재사용)
- `case_bank.md` — 사례 카드 목록
- `profile.md` — 고정 프로필
- `direction.md` — 지향 한 문장, 가고 싶은 자리 / 피할 자리
처음이면 1·2만 하고 끝내도 된다. 다음 실행 때 파일을 받아 이어서 채운다.

## 하지 않는 것
- 사례를 그럴듯하게 부풀리기, 없는 숫자 채우기
- 성격·적성 진단. 지원자가 말한 것만 정리한다
