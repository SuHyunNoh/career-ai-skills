# Career Define — AI가 내 경력을 인터뷰한다

경력기술서만 주고 "고쳐 줘"라고 하면 일반론이 나온다. 이 스킬은 반대로 간다. **질문으로 원재료를 끌어내 쌓아 두고**, 다른 스킬(role-match, business-brief, interview-prep)이 그 재료를 쓴다.

## 입력
- 필수: 경력기술서 또는 이력서
- 선택: 지원자가 쓴 글·메모·포트폴리오, 지원하려는 자리의 공고 1~2개, 이미 있는 사례 은행(갱신할 때)

## 절대 원칙
1. **성과 숫자는 지원자에게서만.** 성과·규모·기간을 추정하거나 만들지 않는다. 비면 질문하고, 답이 없으면 '미확인'으로 둔다. (프로필의 비중처럼 지원자의 사례에서 계산한 값은 '제안값'으로 표시하고 확인받는다.)
2. **숫자마다 기준.** 기간, 비교 대상(0에서 시작한 일이면 "0에서 시작"), 어디서 본 숫자인지(공식 보고 / 대시보드 / 기억). 일부만 알면 아는 만큼 적고 나머지는 '미확인'.
3. **직접 한 것과 팀이 한 것을 구분.**
4. **실패와 한계도 사례다.**
5. **질문은 한 번에 3개 이하.** 물음표가 두 개인 질문은 두 개로 센다.
6. **지원자의 말을 우선.** 다듬되 뜻을 바꾸지 않는다. AI가 추론한 문장은 '초안'으로 표시하고 확인받는다.
7. **같은 칸은 두 번까지만 묻는다.** 두 번 모두 모르면 '미확인'으로 두고 다음으로 간다.

## 워크플로우
0. **연표 확인** — 회사·기간·직함·팀 규모를 한 표로 확인한다. 경력기술서에 빠져 있으면 이것부터 묻는다.
1. **사례 후보 뽑기** — 경력기술서에서 "주도한 일" 단위로 후보 목록(산출물이 아니라 푼 문제 단위). 이력서에 없는 일을 찾는 질문을 한 번 한다(`01_case_bank.md` '빠진 사례 찾기').
2. **사례 채우기** → `references/01_case_bank.md`. 사례 하나씩, 카드를 채운다.
3. **고정 프로필** → `references/02_profile.md`.
4. **지향 정의** → `references/03_direction.md`.
5. **되돌아가기** — 3·4단계에서 새 사례가 나오면 2단계로 돌아가 카드를 만든다.

## 출력 (파일로 남겨 다음에 재사용)
- `case_bank.md` — 연표 + 사례 카드
- `profile.md` — 고정 프로필
- `direction.md` — 지향 한 문장과 가르는 기준
- `transcript.md` — 질문과 답 기록(선택, 갱신할 때 참고)

시간이 없으면 사례 은행과 프로필까지만 하고 끝내도 된다. 다음 실행 때 파일을 받아 이어서 채운다.

## 하지 않는 것
- 사례를 그럴듯하게 부풀리기, 없는 숫자 채우기
- 성격·적성 진단. 지원자가 말한 것만 정리한다
